# Inspection frontier Design handoff

- Status: `completed`
- Updated: `2026-07-25`
- Related design: [[docs/design/design-programs]], [[docs/design/operator-workbench]], [[docs/design/agent-cli-contract]], [[docs/design/coding-agent-optimization]]

## Outcome

Turn the completed inspection supply-path study into current, immutable Design evidence so humans and Agents reopen the same exact rejected frontier instead of being sent back to an apparently unstarted optimization loop.

## Context

Run `089-simulate` correctly ranks `inspection-1` input starvation first. The project-local TypeScript study in `strategies/research/inspection-starvation.ts` evaluates 24 candidates and proves that no explored intervention simultaneously reduces the exact `59.584 s` shortage, improves aggregate score, preserves every current-best case, clears all hard outcomes, and stays within the capital bound.

Before this plan, that conclusion existed only in the plan, README, and research command output. The shared Workbench saw no current Design Run for the commissioned Blueprint and therefore recommended opening the broad `commissioned-dram-fab` brief as though the leading loss had not yet been investigated. This lost work between an Agent and a human and invited repeated evaluation of the same closed route.

INM already has the correct durable contract: a project-local Design Program, current hash-pinned immutable Design Run, explicit rejected iterations, and `frontier-exhausted` authority. This plan uses that contract rather than adding a second research-evidence format.

## Scope

### In scope

- Add a focused authored-seed Design Program for the current inspection supply path.
- Project six distinct shortage-reducing representatives from the 24-case TypeScript study through the locked five-case Benchmark.
- Preserve exact etch quality prevention, physical delivery lanes, capital, energy, area, and current-best zero-regression authority.
- Finish the focused provider as `frontier-exhausted` when every eligible representative is rejected.
- Prefer aligned current Design evidence over an aligned Program with missing evidence when Workbench chooses the shared next action.
- Expose the same exhausted result, rejection reasons, and route through CLI and Studio.

### Out of scope

- Creating a Candidate from a rejected intervention.
- Claiming that every future technology for inspection supply has been exhausted.
- Suppressing the live loss diagnostic or changing its measured severity.
- Replacing the broad commissioned optimization Program.
- Introducing a parallel generic research-record schema.

## Findings and decisions

- 2026-07-25 — Workbench currently chooses the first aligned Program before considering evidence state. `commissioned-dram-fab` is aligned but has zero current Runs, so its brief masks any later aligned Program with current authority.
- 2026-07-25 — The focused Program will retain only shortage-reducing representatives. Score-positive candidates that increase the addressed loss remain in the exploratory TypeScript grid but must not be presented as causal Design repairs.
- 2026-07-25 — `frontier-exhausted` means the authored intervention portfolio is closed for the exact engine, Program, Benchmark, Blueprint, and driver hashes. It does not mean the physical loss can never be improved by a future catalog or topology.
- 2026-07-25 — An optional proposal `addressedLossTarget` names one exact contributor/metric/direction. Core reruns the candidate in the driver case, records full candidate loss evidence plus exact before/after/delta, and blocks promotion or branching when the claimed target does not improve.
- 2026-07-25 — Immediate coverage recovery must still satisfy the positive cadence threshold contract. The representative uses one tick, reducing the exact shortage by `1.000 s`; the remaining five representatives reduce it by `0.667`, `0.667`, `2.000`, `2.500`, and `1.750 s`.
